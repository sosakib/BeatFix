# Feature Specification

Status: 2026-10-08, v1.0. Scope classification: [PRODUCT_SCOPE.md](PRODUCT_SCOPE.md). Authority: [DECISION_SUMMARY.md](../10_implementation/DECISION_SUMMARY.md). Behaviour details live in the linked UI docs. Maths lives in the linked algorithm docs. This file says **what** each feature is, **why** a user wants it, and **which engine parts** it depends on. It does not repeat the specs.

Conventions
- `F-0xx` = MVP. `F-1xx` = post-MVP (Phase 1.5/2/3), listed in §6 for traceability only.
- "Engine dependency" names the module (per [SYSTEM_ARCHITECTURE.md](../05_architecture/SYSTEM_ARCHITECTURE.md)) and the decided library or ADR.
- Personas P1–P4 and journeys J1–J6: [USER_PERSONAS.md](USER_PERSONAS.md). Differentiators D1–D12: [COMPETITIVE_ANALYSIS.md](COMPETITIVE_ANALYSIS.md).
- Acceptance criteria per feature: [ACCEPTANCE_CRITERIA.md](../07_quality/ACCEPTANCE_CRITERIA.md). Metrics: [METRICS.md](../07_quality/METRICS.md).

## 1. Ingest

| ID | Feature and behaviour | User value | Engine dependency | Docs |
|---|---|---|---|---|
| **F-001** | **Import and probe.** One mono/stereo file per window, by drag-drop, Open or Ctrl+O. Formats: WAV (PCM/float/EXTENSIBLE), RF64/BW64, AIFF/AIFF-C, FLAC, MP3, Ogg Vorbis. Probe reports codec, SR, bit depth, bitrate, channels, duration, gapless trim applied (yes/no/unknown) and **effective bandwidth** (e.g. "content ends ~16 kHz, likely lossy origin"). Unsupported (AAC/M4A/Opus): clear message naming the format and its status. Corrupt frames: skipped, counted, shown as an Issue | Any Suno download opens. The user learns what the source really is before judging the output | JUCE readers (WAV/AIFF/FLAC/Ogg), minimp3_ex (MP3) (ADR-009). Effective-bandwidth estimator in `meter` | [UX_BEHAVIOR.md](../06_ui/UX_BEHAVIOR.md) §2, §14–15; [AUDIO_PIPELINE.md](../05_architecture/AUDIO_PIPELINE.md); AUDIO_QUALITY_RESEARCH §4.3 |
| **F-002** | **Decode once, gapless-correct, immutable source.** MP3: skip Xing/Info frame, trim `enc_delay + 529` and padding from the LAME tag. No tag → no trim, flagged "encoder delay unknown". Decoded f32 PCM at native SR is cached and keyed by hash. Fingerprints: file SHA-256/BLAKE3 + PCM hash + decoder version. Analysis and render read the **same** buffer. The source file is never opened for writing | Beats stay sample-aligned with the DAW grid. An untrimmed MP3 would be 25 ms late at 44.1 kHz. No hidden generation loss | Decode + PCM cache (ADR-009, ADR-002). Phase-1 gate: click-track MP3 → 0-sample offset | [AUDIO_PIPELINE.md](../05_architecture/AUDIO_PIPELINE.md); AUDIO_QUALITY_RESEARCH F1–F2, §4.10 |

## 2. Analysis (the beat map)

| ID | Feature and behaviour | User value | Engine dependency | Docs |
|---|---|---|---|---|
| **F-003** | **Full-song beat tracking.** Beat This! (final model) ONNX on ORT CPU produces 50 fps beat/downbeat activations. Our own DP decoder runs with a ±40 % tempo corridor, then missing/extra-beat repair, parabolic sub-frame refinement, optional percussive transient snap with **global** offset correction. The DSP tracker (HPSS + SuperFlux → same decoder) always runs as cross-check and is the fallback if the model fails ("DSP mode", global confidence capped at Medium). Activations + model hash are persisted. Staged, cancellable progress. Original playback is available as soon as decode ends | Accurate, continuous anchors without manual markers (D1). Reopening a project never re-runs inference | `bf_analysis`: ORT 1.30 CPU EP, Beat This MIT weights, owned decoder (ADR-003). Telemetry disabled | [ONSET_DETECTION.md](../04_algorithms/ONSET_DETECTION.md), [BEAT_TRACKING.md](../04_algorithms/BEAT_TRACKING.md), [OUTLIER_REJECTION.md](../04_algorithms/OUTLIER_REJECTION.md); [MAIN_WINDOW.md](../06_ui/MAIN_WINDOW.md) §4.2 |
| **F-004** | **Downbeats and meter.** Bar phase and meter ∈ {3, 4} by windowed voting on downbeat activation, with a Viterbi that penalises meter/phase changes. Irregular bars are flagged, not hidden | Correct bar numbers. Bar 1 lands on a target bar line. DAW-ready start (F-020) works | `bf_analysis` | [DOWNBEAT_ESTIMATION.md](../04_algorithms/DOWNBEAT_ESTIMATION.md); BEAT_TRACKING_RESEARCH §4 |
| **F-005** | **Tempo estimate + ranked hypotheses.** Global BPM by Huber-IRLS line fit on beats, Theil–Sen cross-check (> 0.05 BPM disagreement flagged), shown with 2 decimals ± uncertainty. Candidates `B̂ × {1/3, 1/2, 2/3, 1, 3/2, 2, 3}` within 40–250 BPM, scored on salience, activation contrast, downbeat consistency, backbeat, weak 120 BPM prior. Margin → Green/Amber/Red | Octave errors (≈ 1 in 6–8 songs on generic data) become a one-click choice instead of a hidden ×2 button (D3) | `bf_analysis` tempo module (ADR-004) | [BPM_ESTIMATION.md](../04_algorithms/BPM_ESTIMATION.md), [HALF_DOUBLE_TIME_RESOLUTION.md](../04_algorithms/HALF_DOUBLE_TIME_RESOLUTION.md); [MAIN_WINDOW.md](../06_ui/MAIN_WINDOW.md) §4.5 |
| **F-006** | **Confidence.** Per-beat score = logistic over activation, salience, ML↔DSP agreement (±35 ms), residual, IOI consistency, clean snap. Global level High / Medium / Low / None, **always with a reason** in words. Thresholds are placeholders in one versioned config, calibrated on the corpus before release (DECISION_SUMMARY §3.5) | The user knows when one-click is safe and when to listen (D2). P1 sees "High", P4 sees why | `bf_analysis` | [BEAT_TRACKING.md](../04_algorithms/BEAT_TRACKING.md); [MAIN_WINDOW.md](../06_ui/MAIN_WINDOW.md) §4.4; [UX_BEHAVIOR.md](../06_ui/UX_BEHAVIOR.md) §4 |
| **F-007** | **Tempo stability and anomaly detection.** Change points and phase jumps are found first on robust residuals. Then per-segment Whittaker smoothing classifies each segment as Stable / Drifting / Stepped / Spliced / Level switch / Unreliable. Each class is shown with a number (e.g. "Slight drift, max 84 ms"). Events (step, splice, level switch) become timeline markers and Issues | The user sees *whether* and *where* the song wanders before deciding anything | `bf_analysis` (shared Whittaker code with the warp module) | [TEMPO_STABILITY_ANALYSIS.md](../04_algorithms/TEMPO_STABILITY_ANALYSIS.md); TEMPO_ESTIMATION_RESEARCH §5 |
| **F-008** | **Interpretation edits.** Pick a candidate, ½ / ×2, Set bar 1 at cursor (snaps to the nearest beat within ±½ beat), meter 3/4 ↔ 4/4, accept/reject a detected change point. Each edit is one undoable command and re-runs decode/post-processing from cached activations (sub-second), never inference | Fix *what was heard* without touching audio (D6). Melodyne-style Assign vs Edit, our own UI | `bf_analysis` steps 4–8 (BEAT_TRACKING_RESEARCH §12) | [UX_BEHAVIOR.md](../06_ui/UX_BEHAVIOR.md) §5; [KEYBOARD_SHORTCUTS.md](../06_ui/KEYBOARD_SHORTCUTS.md) |

## 3. Correction (target and warp)

| ID | Feature and behaviour | User value | Engine dependency | Docs |
|---|---|---|---|---|
| **F-009** | **Target BPM.** Default = `round(bpmGlobal)`, shown as "detected 107.55 → suggested 108". Offer the .5 value if the song is stable and the fractional part > 0.25. Manual entry to 0.01 BPM. Values whose ratios fall outside the hard bounds (0.5–2.0) are rejected with the allowed range shown. Overall change > 15 % raises an Issue. ↺ restores the suggestion | Sane one-click target for fixed-BPM workflows. Exact value visible for P2/P4 | `bf_dsp` warp module | [BPM_ESTIMATION.md](../04_algorithms/BPM_ESTIMATION.md) §5; [UX_BEHAVIOR.md](../06_ui/UX_BEHAVIOR.md) §6 |
| **F-010** | **Target grid and warp map.** Grid `T_k = φ + k·60/B`. Slot assignment preserves beat count. W is piecewise-linear and strictly monotone, from smoothed anchors. W and W⁻¹ are f64, shared by renderer, playback and UI (the UI never re-implements interpolation). `WarpMap::validate()` enforces Δ_min, hard ratio bounds 0.5–2.0 and a warn band of 0.92–1.08. JSON with `schemaVersion` / `algoVersion` / `inputsHash`, derived from persisted inputs | A mathematically consistent correction that can be inspected and reproduced | `bf_dsp` warp module (ADR-005) | [TARGET_BEAT_GRID.md](../04_algorithms/TARGET_BEAT_GRID.md), [WARP_FUNCTION.md](../04_algorithms/WARP_FUNCTION.md), [WARP_MAP.md](../04_algorithms/WARP_MAP.md) |
| **F-011** | **Natural ↔ Strict.** Six detents set the smoother cutoff N_c ∈ {Global (∞), 32, 16, **8 (default, "Natural")**, 4, Strict (λ = 0)} beats. Deviations faster than N_c (groove, swing, detector noise) are kept. Slower ones (drift, ramps) are corrected. Live readout: `grid err ≤ X ms` and `max ±Y %`. Each detent is one undo step | Removes drift without flattening the groove, and keeps detector jitter out of the output (D4). The trade-off is visible as numbers | `bf_dsp` Whittaker/IRLS smoother | [WARP_FUNCTION.md](../04_algorithms/WARP_FUNCTION.md) §4; [MAIN_WINDOW.md](../06_ui/MAIN_WINDOW.md) §3 |
| **F-012** | **Intentional tempo-change handling.** A detected step (default: ask when > 5 %, placeholder) or level switch is flagged with two choices: **flatten to target**, or **keep this section unwarped (r = 1)**. The smoother break (`g_i = 0`) means a step is never smeared into a ramp. Splices are flagged and never spread over N_c beats | Protects deliberate musical changes (ritardando, halftime bridge). Admits what one-click tools get wrong (D9) | `bf_analysis` change points + `bf_dsp` smoother segments | [TEMPO_STABILITY_ANALYSIS.md](../04_algorithms/TEMPO_STABILITY_ANALYSIS.md); DECISION_SUMMARY §6 |

## 4. Render and preview

| ID | Feature and behaviour | User value | Engine dependency | Docs |
|---|---|---|---|---|
| **F-013** | **Render from source.** Every change re-renders from the decoded PCM cache, never from a previous render or export. Chunk-parallel render cut at quiet beat boundaries every 8–16 beats, with pre-roll and crossfade. Deterministic regardless of core count. Content-addressed per-chunk cache, so a local edit invalidates only nearby chunks. Rendering starts at the playhead chunk, then forward, then backward. Audio from an obsolete edit state is never played as B. Single-pass render is kept as the null-test reference | Changing BPM, strength or mode is cheap and loss-free (D7). Hear the edit near the playhead quickly (provisional target ≤ 500 ms) | `bf_engine` render pool, cache (ADR-007, ADR-011) | [RENDER_PIPELINE.md](../05_architecture/RENDER_PIPELINE.md), [THREADING_MODEL.md](../05_architecture/THREADING_MODEL.md); [UX_BEHAVIOR.md](../06_ui/UX_BEHAVIOR.md) §9 |
| **F-014** | **Stretch modes (MVP set).** **Smooth** (default): Signalsmith Stretch 1.4.0, driven by W⁻¹ on a fixed output hop, linked stereo (inter-channel phase difference preserved), drift-free integer rounding. **Resample**: r8brain varispeed, allowed only on constant-ratio material, pitch shift shown in cents. Preview quality Fast / High (separate cache key). Export always uses the highest quality. Mode change keeps timing identical and re-renders audio only | Pitch-preserving correction with stable stereo image. Artifact-free varispeed for those who accept the pitch change | `ITimeStretcher` (ADR-006). Transient mode is Phase 1.5 | [TIME_STRETCH_ENGINE.md](../04_algorithms/TIME_STRETCH_ENGINE.md), [STEREO_PHASE_PRESERVATION.md](../04_algorithms/STEREO_PHASE_PRESERVATION.md), [RESAMPLING.md](../04_algorithms/RESAMPLING.md); [UX_BEHAVIOR.md](../06_ui/UX_BEHAVIOR.md) §8 |

## 7. Known limitations of the MVP feature set
- No manual anchors: if the detector is wrong *locally* and the beat-level edits can't fix it, the user's only tools are Natural (down-weights the error) or "keep section unwarped". This is accepted for MVP. F-102 removes it.
- "None" confidence (no steady beat) means export is disabled. Correct, but P1 gets nothing for beatless material.
- Thresholds for confidence, stability classes and heat classes are placeholders until corpus calibration. Behaviour can shift before release.
- Preview at "Fast" can sound slightly different from export. The UI states this.
